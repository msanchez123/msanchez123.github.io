# 🎮 Arcade

A dashboard of small games, hosted on GitHub Pages. Each game is a self-contained folder with its own `index.html`, and multiplayer is powered by [Trystero](https://github.com/dmotz/trystero) — no backend, no accounts, no config.

**Add a game = add a folder. That's it.** A GitHub Action scans the repo on every push and regenerates `games.json`, which the dashboard reads. You never edit the dashboard or any manifest by hand.

## ➕ Adding a game

1. Create a folder at the repo root, e.g. `snake/`
2. Put an `index.html` in it — that's the game's entry point
3. *(Optional)* add `snake/meta.json` to customize the tile:

   ```json
   {
     "name": "Snake",
     "icon": "🐍",
     "desc": "Eat, grow, survive"
   }
   ```

   | Field  | Default                         | Notes                                                    |
   | ------ | ------------------------------- | -------------------------------------------------------- |
   | `name` | Folder name, title-cased        | `my-new-game` → `My New Game`                            |
   | `icon` | `🎮`                            | Emoji, relative path (`./icon.png`), or full URL         |
   | `desc` | *(none)*                        | Short subtitle under the tile                            |

4. Commit and push

The Action runs, updates `games.json`, and the new tile appears on the dashboard — no other edits needed.

> Folders without an `index.html` are ignored. Dotfiles, `.github/`, and `node_modules/` are skipped.

## 🚀 First-time setup

1. **Create the repo.** If you want the site at `https://<user>.github.io/`, name the repo `<user>.github.io`. Otherwise any repo name works and the site lives at `https://<user>.github.io/<repo>/`.

2. **Add the three files** from this repo's root:
   - `index.html` (the dashboard)
   - `.github/workflows/generate-games.yml` (the Action)
   - `games.json` containing `[]` (bootstrap — the Action overwrites it)

3. **Enable Pages.** Repo → **Settings → Pages** → Source: **Deploy from a branch** → Branch: `main`, folder: `/ (root)` → Save.

4. **Push.** The Action runs on `main`. Once it completes, `games.json` is populated and the dashboard loads.

5. **Check Actions permissions.** Repo → **Settings → Actions → General → Workflow permissions** → **Read and write permissions** must be selected, or the Action can't commit the updated manifest.

That's it. From here on, adding games requires touching nothing but the new game folder.

## 🔧 How it works

```
push to main
      │
      ▼
GitHub Action scans root folders for index.html
      │
      ▼
writes games.json   (name from meta.json, or title-cased folder name)
      │
      ▼
commits games.json back to main  (only if it changed)
      │
      ▼
dashboard fetches ./games.json  →  renders tiles
```

### Why a manifest and not auto-discovery?

GitHub Pages serves static files and has **no directory listing API**. A browser can't ask "what folders exist here?" — so pure frontend JS can't discover games on its own. Generating a manifest at build time is the only way to get true "drop a folder and forget it" behavior.

The Action uses `[skip ci]` on its commit so the manifest update doesn't loop.

### Why Trystero works fine here

Trystero is pure client-side JS — GitHub Pages is just static hosting, so there's nothing extra to configure. Each game is its own page at its own URL and runs its own Trystero config.

**One rule:** give each game a **distinct `appId`** (or a namespaced `roomId`). Two different games sharing the same `appId` + `roomId` could see each other's peers. Example:

```js
import { joinRoom } from 'https://esm.sh/trystero'

const room = joinRoom({ appId: 'my-arcade-tetris' }, 'lobby')
```

If you use the Firebase strategy across games, also set a unique `rootPath` per game so signaling data doesn't collide.

## 🧪 Local testing

The dashboard fetches `games.json`, so serve the folder over HTTP (opening `index.html` via `file://` will fail the `fetch` due to CORS):

```bash
# Python
python3 -m http.server 8000

# Node
npx serve .
```

Then open <http://localhost:8000/>.

Locally, `games.json` won't auto-update (the Action only runs on push). To regenerate it manually:

```bash
python3 -c "
import json, os
skip = {'.github', 'node_modules'}
games = [
    {'name': d.replace('-',' ').title(), 'folder': d}
    for d in sorted(os.listdir('.'))
    if os.path.isdir(d) and not d.startswith('.')
    and d not in skip and os.path.isfile(f'{d}/index.html')
]
json.dump(games, open('games.json','w'), indent=2)
"
```

## 🩺 Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Dashboard shows "Could not load `games.json`" | Action hasn't run yet, or `games.json` missing | Push a commit, wait for the Action, check the **Actions** tab |
| New game doesn't appear | Folder is missing `index.html`, or Action failed | Check the run log in **Actions** |
| Action fails with "permission denied" on push | Workflow permissions are read-only | Settings → Actions → General → **Read and write permissions** |
| Game 404s after clicking its tile | Folder name has uppercase or spaces | Rename to lowercase, no spaces (Pages is case-sensitive) |
| Two games see each other's players | Shared `appId` + `roomId` | Give each game a unique `appId` in its Trystero config |
| Assets broken inside a game | Absolute paths like `/style.css` | Use relative paths: `./style.css` |
